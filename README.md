# Платформа онлайн-записи для мастеров

У каждого мастера своя страница `/<адрес>` и свой личный кабинет `/<адрес>/admin`.
Мастера никак не связаны друг с другом: у каждого своя папка с данными, свой пароль, свои записи и отзывы.

## Запуск за 5 шагов

**1. Откройте PowerShell в папке проекта.**
Откройте папку в Проводнике, нажмите в адресной строке, напишите `powershell` и нажмите Enter.

**2. Вставьте одну команду и нажмите Enter:**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

Скрипт сам проверит Node.js (при необходимости установит), поставит компоненты, при первом запуске спросит **пароль платформы** (придумайте и запишите), создаст двух демо-мастеров и откроет панель в браузере.
Если Windows спросит про доступ к сети, нажмите «Разрешить доступ». Повторный запуск безопасен.

**3. Создайте мастера.**
В панели откройте «Новый мастер» и вставьте анкету. Это обычный текст (образец: кнопка «Вставить пример» и вкладка «Как заполнять анкету»). Нажмите «Проверить»: увидите, как всё распознано. Жёлтым подсвечено то, что стоит поправить, но это не мешает создать мастера. Нажмите «Создать мастера». Несколько анкет подряд разделяйте строкой `---`.

**4. Отправьте мастеру приглашение.**
На экране «Готово» нажмите «Скопировать сообщение» (или «Поделиться») и отправьте его мастеру. Ссылка одноразовая и действует 7 дней. По ней мастер придумает пароль и сам заполнит всё остальное в кабинете с телефона. Забыл пароль? «Мастера» → «Новое приглашение».

**5. Резервная копия.**
Скопируйте папку `masters` (в ней всё: профили, услуги, записи, фото). Копию одного мастера скачивает кнопка «Копия (zip)» в списке мастеров.

Остановить платформу: закройте окно PowerShell.

## Что умеет панель платформы (`/platform`)

- **Новый мастер**: анкета → проверка → создание, фото, адрес страницы (создаётся автоматически, можно изменить), готовое сообщение мастеру.
- **Мастера**: открыть страницу, скопировать ссылку, новое приглашение / сброс доступа, резервная копия, приостановить («Запись временно недоступна»), изменить адрес, архивировать. Записи клиентов здесь не показываются.
- Панель открывается **только с этого компьютера**. Чтобы открыть её снаружи, поставьте в `config/platform.json` значение `"allowExternal": true` (делайте это только при необходимости и с надёжным паролем).

## Публикация в интернете

Платформа слушает порт 3000 (меняется в `config/platform.json`, поле `port`). Чтобы страницы открывались у клиентов, запустите её на сервере с доменом или пробросьте через туннель (например, Cloudflare Tunnel). Затем в панели «Мастера» укажите **адрес сайта** (например, `https://zapis.example.ru`): он попадёт в ссылки и сообщения мастерам.

## Что где лежит

| Папка / файл | Назначение |
|---|---|
| `start.ps1` | единственная команда запуска |
| `masters/<адрес>/` | всё, что принадлежит мастеру: `master.json`, `services.json`, `schedule.json`, `reviews.json`, `bookings.json`, `auth.json`, `backups/` (последние 30 копий каждого файла), `photos/` |
| `config/platform.json` | название платформы, пароль платформы (хэш), адрес сайта, порт |
| `template/` | эталонная папка нового мастера |
| `archive/` | удалённые мастера |
| `engine/` | код платформы (туда заходить не нужно) |

Данные хранятся в обычных JSON-файлах, и они единственный источник правды. Если поправить файл вручную, изменения видны сразу, без перезапуска. Подсказки по-русски лежат в поле `_подсказка` каждого файла (оно сохраняется при правках из кабинета). Комментарии `//` в файлах читаются, но при сохранении из кабинета в этом файле не сохраняются.

Если файл сломан при ручной правке, остальные мастера работают как обычно, а кабинет этого мастера предлагает восстановить файл из последней копии.

## Служебные скрипты (необязательно)

Всё это делается кнопками в панели, скрипты для тех, кто любит командную строку:
`new-master.ps1 -File anketa.txt`, `reset-access.ps1 -Slug arina`, `remove-master.ps1 -Slug arina`. Запускать так же, через `powershell -NoProfile -ExecutionPolicy Bypass -File .\имя.ps1 ...`.

Забыли пароль платформы? В PowerShell в папке проекта:
```powershell
$env:PLATFORM_PASSWORD = 'новый-пароль-не-короче-8'; node engine\cli.js set-password; Remove-Item Env:PLATFORM_PASSWORD
```

## Демо

Мастера `demo` и `demo-lavender` создаются при первом запуске. Пароль их кабинетов: **demo12345**. Когда они не нужны, отправьте их в архив кнопкой в списке мастеров.

## Telegram-уведомления мастеру

Мастер подключает их сам в кабинете («Профиль» → «Уведомления в Telegram») по пошаговой инструкции: создаёт бота у @BotFather, вставляет токен, нажимает «Найти chat id» и «Отправить тест».

В Telegram-сообщении **нет личных данных клиента**: только дата, время, услуги, сумма и, если клиент сам указал при записи необязательное поле «Telegram», его логин (`@username`). Имя, телефон и комментарий в Telegram не отправляются; их мастер видит в кабинете на вкладке «Записи».

## Уведомления о записях

- **Push на телефон или компьютер.** Мастер включает их сам: «Профиль» → «Push-уведомления» → «Включить на этом устройстве» (на вкладке «Записи» тоже есть подсказка). Уведомления приходят о новых записях, отменах и переносах клиентом и о новых отзывах, даже когда кабинет закрыт.
- **Нужен HTTPS.** Push работают только на защищённом адресе (`https://…`) или на `localhost`. На обычном `http://` по IP-адресу кнопка будет недоступна. Об этом в кабинете есть подсказка.
- **iPhone:** мастеру нужно добавить кабинет на экран «Домой» (Safari → «Поделиться» → «На экран “Домой”»), открыть его оттуда, войти по паролю и включить уведомления (iOS 16.4 и новее). Внутри значка вход отдельный от Safari: пароль придётся ввести заново.
- **Telegram** по-прежнему работает отдельно и независимо от push.
- Ключи для push (VAPID) создаются автоматически при первом использовании и хранятся в `config/platform.json`. Не меняйте их: после замены все подключённые устройства придётся включать заново. Контактный адрес для сервисов push можно поменять в поле `vapid.subject` (по умолчанию `mailto:admin@example.com`).

## Проверка

При запущенной платформе: `node tests/acceptance.js` (86 автоматических проверок: изоляция мастеров, слоты, записи, приглашения, сброс доступа, восстановление файлов).

## Размещение на сервере (Timeweb Cloud и любой Ubuntu-VPS)

1. Создайте облачный сервер Ubuntu 22.04/24.04 и запишите IP и пароль root.
2. В PowerShell в папке проекта: `powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy.ps1`. Скрипт всё поставит сам (Node.js, HTTPS через Caddy, автозапуск, файрвол). Тот же запуск обновляет проект, данные мастеров при этом не затрагиваются.
3. Панель платформы на сервере закрыта от интернета. Открывать её: `.\panel.ps1 -Ip <IP>`.
4. Резервная копия данных: `.\backup.ps1 -Ip <IP>`.
